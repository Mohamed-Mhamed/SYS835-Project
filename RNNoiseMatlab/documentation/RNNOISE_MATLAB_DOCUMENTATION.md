# RNNoiseMatlab: technical documentation

## 1. Scope and status

`RNNoiseMatlab` is a reproducible MATLAB experiment harness for the official
RNNoise reference implementation. It is **not** a MATLAB implementation of
the RNNoise neural network. MATLAB loads signals, creates a controlled
mixture, performs a transparent 8 kHz-to-48 kHz conversion, writes PCM, starts
the locally compiled official executable, reads its PCM output, aligns and
scores the result, and exports validation vectors. The denoising algorithm
(feature extraction, recurrent neural network, gain calculation, synthesis,
and persistent denoiser state) remains in the official C library/executable.

This distinction is important for both scientific honesty and portability:
the project demonstrates how to prepare and evaluate RNNoise, whereas a
future C6713 implementation must port or replace the official C runtime
itself. The production path is the local polyphase FIR plus
`rnnoise_demo`; MATLAB `resample` is only an optional validation reference.

The project is self-contained under:

```text

```

## 3. Signal and experiment contracts

### 3.1 Input data

`load_sigd` expects a MATLAB file containing a variable named `sigd`. It
converts it to a finite, double-precision column vector and rejects missing,
empty, or non-finite data. The project treats the course data as **8,000 Hz**:
the older 8,192 Hz assumption is deliberately not used here.

The default pair is:

```text
data\Signal\1z88153a8.mat
data\Bruit\white8.mat
```

Other supplied noise files include `pink8.mat` and `volvo8.mat`; other speech
files are in `data\Signal`.

### 3.2 Controlled mixture

`create_noisy_signal(clean, noise, targetSNRdB)` first removes the noise mean,
repeats the noise periodically until it is at least as long as speech, and
truncates it to the speech length. With

\[
 E_s=\sum_n s[n]^2,\qquad E_v=\sum_n v[n]^2,
\]

the scale

\[
 a=\sqrt{\frac{E_s}{10^{SNR_t/10}E_v}}
\]

produces `noisy = clean + a*noise`. The measured source SNR is recomputed from
the scaled vectors and stored in `mixInfo.MeasuredSNRdB`; it is not assumed
to equal the requested value after finite precision.

The clean reference is used only by the experiment harness for mixture
creation and evaluation. It is never supplied to RNNoise.

### 3.3 Optional noise-only prefix

When `AddNoiseOnlyPrefix` is true, `add_noise_prefix` prepends
`NoiseOnlyPrefixSeconds` (default 0.25 s, or 2,000 samples at 8 kHz) of
noise-only audio:

```text
clean reference:  [zeros | clean speech]
noisy input:      [noise | clean + scaled noise]
noise reference:  [noise | scaled noise]
```

The prefix is an experiment protocol aid, useful when comparing systems that
need an initial noise observation. It is not an RNNoise noise-estimator input
or a special RNNoise mode: RNNoise receives the complete noisy stream and
uses its own internal state. `NoisePrefixSamples` is saved in the result
metadata. The metric reference includes the corresponding zero prefix, so a
user comparing speech-only quality should explicitly report whether the prefix
was excluded.

## 4. 8 kHz-to-48 kHz FIR resampler

### 4.1 Why it is required

The experiment data is 8 kHz but the official RNNoise API contract is 48 kHz.
The rational conversion is an integer interpolation by

\[
L=\frac{48\,000}{8\,000}=6.
\]

Every input sample therefore produces six output samples. The clean signal,
noisy signal, and noise reference all use the **same** filter and boundary
rules, preserving their relative timing and making post-processing meaningful.

### 4.2 Design

`design_fir_resampler(97)` returns a `6 x 97` coefficient matrix. Each row is
one fractional-delay phase. For phase \(p\in\{0,\ldots,5\}\), tap \(n\), and
center \(N_c=48\):

\[
t=n-N_c-\frac{p}{6},
\qquad
h_p[n]=\frac{\sin(\pi t)}{\pi t}\,w[n],
\]

where the value at \(t=0\) is one and

\[
w[n]=0.54-0.46\cos\left(\frac{2\pi n}{96}\right)
\]

is a Hamming window. The ideal sinc is the interpolation low-pass response;
windowing makes the finite 97-tap truncation less discontinuous and reduces
sidelobes/images. Each phase is normalized by its coefficient sum:

\[
h_p[n]\leftarrow h_p[n]/\sum_n h_p[n].
\]

This gives unity DC gain for every fractional phase. The odd tap count gives
a central sample and symmetric finite support (with the fractional phase shift
represented explicitly). The selected length is a transparent compromise
between stopband quality, memory, and a future C6713 MAC budget; it is not
claimed to be MATLAB's filter.

The returned `design` records input/output rates, interpolation factor, tap
count, cutoff description, and a C-portable description. `FirCutoffInputCycles`
in `default_config` documents the intended normalized cutoff; the current
coefficient routine's sinc is the authoritative implementation.

### 4.3 Polyphase evaluation and boundaries

`resample_fir_8k_to_48k` computes output index \(m\):

\[
r=m/6,\quad i=\lfloor r\rfloor,\quad p=(m\bmod6)+1,
\]

then takes a 97-sample neighborhood around \(i\) and computes its dot product
with phase row \(p\). It does not allocate a zero-stuffed six-times signal.
Out-of-range input indices are zero, so finite-recording beginning/end
regions contain zero-extension transients and the result length is exactly
`6*length(input)`.

This implementation is intentionally readable MATLAB. A streaming C version
should replace the temporary tap vector with a circular history buffer and
fixed direct MAC loops, while preserving phase order and boundary policy.

### 4.4 Validation against MATLAB `resample`

`validate_fir_resampler` always runs the local FIR first. If the Signal
Processing Toolbox supplies `resample`, it computes
`resample(input,6,1)`, searches a bounded delay range (±`6*97` samples) using
absolute normalized correlation, aligns the two signals, and reports:

* local and reference lengths;
* detected delay;
* RMS and maximum absolute error;
* relative RMS and relative maximum error;
* status and reference availability.

If `resample` is unavailable, no toolbox dependency is introduced: the report
states that fact and the tests still exercise deterministic DC and sinusoidal
signals. `resample` is **never** used by production conversion.

The recorded speech/reference comparison was approximately 129,354 samples
for each method, RMS difference 1.378, maximum difference 10.357, and about
0.1% relative RMS error (the exact values belong to the saved run and can
vary with inputs). The deterministic sinusoid previously reported
approximately 0.000846 RMS, 0.0153 maximum error, 0.00120 relative RMS, and
zero detected delay. These numbers demonstrate close behavior for tested
signals, not bit equivalence: MATLAB uses a different design, order, delay
convention, and endpoint handling.

## 5. RNNoise 48 kHz/480-sample contract

The official interface processes one mono frame of 480 samples at 48 kHz:

\[
480/48\,000=10\text{ ms}.
\]

`prepare_frames` appends zeros so the input length is an integer multiple of
480 and returns the padding count. The main script applies the same padding
to clean and noise references. This padding is recorded as `PaddingSamples`.
The official state must persist across all calls; resetting the state per
frame would not represent the runtime.

The contract includes more than a size constant:

* one channel;
* 48,000 samples/second;
* 480 samples per call;
* sequential calls on one `DenoiseState`;
* float samples at the API boundary, with this demo transporting them through
  signed PCM16;
* no clean/reference signal in the processing call.

## 6. PCM and official executable path

### 6.1 MATLAB serialization

`write_pcm16` writes mono signed 16-bit integers, little endian, after
clamping to [-1,1] and multiplying by 32767. If the signal peak exceeds one,
it applies a common 0.99 scale before quantization. `read_pcm16` reads
little-endian `int16` and divides by 32768, returning a double column vector.
Consequently, PCM is a transport format, not a lossless representation of
the MATLAB doubles. The main experiment first applies a common scale to clean,
noisy, and noise signals so the noisy input peak is at most 0.99.

`run_rnnoise_reference` constructs, on Windows:

```text
wsl.exe "<translated executable>" "<translated input>" "<translated output>"
```

`to_wsl` converts an absolute Windows path such as `C:\x\y` to
`/mnt/c/x/y`. On non-Windows systems it invokes the executable directly.
The helper checks process status, output existence, and nonzero output size.

### 6.2 What `rnnoise_demo.c` actually does

The local source is `rnnoise\examples\rnnoise_demo.c`. It defines
`FRAME_SIZE 480`, creates one `DenoiseState` using `rnnoise_create(NULL)`
(or a weights file when compiled with `USE_WEIGHTS_FILE`), reads blocks of
480 `short` values, converts each to `float` without a `/32768` scaling,
calls:

```c
rnnoise_process_frame(st, x, x);
```

and converts the 480 float outputs back to `short` for output. The input and
output file arguments are raw binary mono streams; there is no WAV header,
sample-rate field, channel field, or metadata. The demo intentionally omits
the first processed block (`if (!first) fwrite(...)`), allowing the recurrent
runtime to warm up. Therefore output is normally one 480-sample frame shorter
than input. It also assumes complete reads and does not perform a WAV-style
clipping or metadata conversion. Those are properties of this reference
wrapper, not MATLAB promises and not a complete embedded I/O design.

The local `.libs` files are build artifacts. The executable is a desktop/WSL
reference tool, not a C6713 binary. Exact model symbols, DSP internals, and
network weights should be taken from the corresponding official RNNoise
source/header used to build the artifact; this project does not duplicate
those internals in MATLAB.

### 6.3 Alignment

`align_output` searches candidate delays from `-maxDelay` to `+maxDelay`
(the main script uses twice the 480-sample frame size). For each candidate it
subtracts each segment mean and scores absolute normalized correlation:

\[
\rho=\frac{|\sum (r-\bar r)(y-\bar y)|}
{\sqrt{\sum(r-\bar r)^2\sum(y-\bar y)^2}}.
\]

The best candidate is retained in `delay`; the function returns only the
overlapping aligned vectors. Alignment compensates for runtime warm-up,
buffering, and finite-recording effects for evaluation. It does not alter the
saved unaligned PCM and must not be confused with removing the FIR group
delay. The detected delay is saved and printed.

## 7. Main non-GUI experiment

`no_gui\main_rnnoise_matlab.m` performs the complete production sequence:

1. clears figures/console and adds `core`;
2. obtains `default_config`;
3. locates the local executable;
4. loads clean speech and noise;
5. creates the target-SNR mixture;
6. optionally prepends the noise-only prefix;
7. designs and validates the FIR;
8. resamples clean, noisy, and noise-reference signals;
9. truncates them to a common length and applies common peak scaling;
10. pads the noisy signal to 480-sample frames and mirrors its padding;
11. writes `generated\pcm\noisy_input_48k.pcm`;
12. invokes the official executable and reads its output;
13. aligns output to clean reference;
14. computes metrics and records source SNR, delay, prefix, and padding;
15. exports frame matrices, MAT metadata, float32 files, plots, and optional audio.

`default_config` selects 8 kHz input, 48 kHz RNNoise, 480-sample frames,
10 dB target SNR, 97 FIR taps, the default files, a 0.25 s prefix, plots and
playback enabled. These are experiment defaults, not immutable RNNoise API
requirements except for 48 kHz/480 samples.

## 8. Metrics, plots, and playback

`calculate_metrics` truncates all three aligned vectors to their common
length. With \(e_i=noisy-clean\) and \(e_o=enhanced-clean\):

\[
SNR_i=10\log_{10}\frac{\sum clean^2}{\max(\sum e_i^2,\epsilon)},\qquad
SNR_o=10\log_{10}\frac{\sum clean^2}{\max(\sum e_o^2,\epsilon)},
\]

\[
\Delta SNR=SNR_o-SNR_i.
\]

It also reports input/output MSE, RMSE, and sample count. These are
reference-based waveform metrics; they do not replace perceptual measures
such as PESQ, STOI, or listening tests.

`plot_results` writes four time-domain waveforms (clean, noise, noisy,
enhanced) and three spectrograms (clean, noisy, enhanced) using a 960-sample
Hamming window, 480-sample hop, 1024-point FFT, and a floor of `1e-8` before
the logarithm. The plots are diagnostic, not part of the denoiser.

`play_audio_signal` checks finite nonempty data and normalizes only its
temporary playback copy to 0.95 peak. Thus listening normalization does not
change metrics or saved signals. The main path plays original speech, noise,
noisy speech, and enhanced speech in that order when `PlayAudio` is true.

## 9. GUI

`gui\rnnoise_gui.m` creates a `uifigure` with clean/noise file fields, target
SNR, prefix checkbox, run button, four playback buttons, and a status area.
The run callback repeats the same preparation, FIR, PCM, executable, alignment,
metrics, and plot sequence as the non-GUI path, then stores the four processed
signals in closure variables. It is a front end, not a second algorithm.
Errors are displayed with `getReport(...,'basic')`; playback before a
successful run reports “Run the experiment first.”

The GUI currently uses its own concise orchestration and fixed 960-sample
alignment bound, whereas the non-GUI path also saves the complete metadata
and CCS vectors. For publication-quality reproducibility, use the non-GUI
entry point and treat the GUI as an interactive convenience.

## 10. Tests and generated CCS vectors

Run:

```matlab

```

The tests verify a `6 x 97` FIR, nonempty FIR validation status, deterministic
constant and sinusoidal behavior, 480-frame padding, PCM round-trip length,
finite metric values, and a 48 kHz design rate. When available they print
RMS/max comparison information against MATLAB `resample`. They do not prove
that the neural runtime is correct; the official executable is treated as the
reference under test.

The main run exports:

* `generated\results\rnnoise_results.mat`: configuration, FIR, validation,
  mixture/runtime metadata, metrics, delay, and frame matrices;
* `generated\ccs_vectors\rnnoise_vectors.mat`: `inputFrames`,
  `cleanFrames`, `enhancedFrames`, `config`, and `fir`;
* `generated\ccs_vectors\input_frames_480_float32.dat`;
* `generated\ccs_vectors\clean_frames_480_float32.dat`;
* `generated\ccs_vectors\enhanced_frames_480_float32.dat`;
* `generated\ccs_vectors\fir_coefficients.mat`;
* generated PCM and figures.

Each frame matrix is `480 x frameCount`, with one frame per column. Binary
float32 files are little endian and follow MATLAB column-major linear order,
which means each column's 480 samples is contiguous. CCS/host C readers must
preserve this order, type, endianness, and frame count. The clean vectors are
reference-only; the embedded denoiser must consume only input frames.

## 11. Exact mapping to official RNNoise concepts

| MATLAB project concept | Official/runtime concept |
|---|---|
| `config.FsRNNoise = 48000` | RNNoise full-band sample-rate contract. |
| `config.FrameSize = 480` | `FRAME_SIZE` and one `rnnoise_process_frame` call. |
| `prepare_frames` | Complete input blocks required by the C loop. |
| sequential executable processing | One persistent `DenoiseState *st`. |
| `noisy48` only at runtime | In-place `rnnoise_process_frame(st,x,x)`. |
| `write_pcm16` | `short tmp[FRAME_SIZE]` file transport. |
| `read_pcm16` | C output `short` stream returned to MATLAB. |
| optional prefix | External experiment protocol, not RNNoise's estimator. |
| FIR output | Rate-conversion front end before RNNoise. |
| clean/noise vectors | Evaluation references, never network inputs. |
| `rnnoise_demo` | Official C wrapper and compiled library/model. |

The paper's high-level description is a hybrid DSP/deep-learning denoiser:
frequency-domain analysis and synthesis surround an RNN that estimates
speech/noise behavior and suppression gains. This document deliberately does
not infer or reproduce hidden feature dimensions, recurrent weights, training
normalization, SIMD kernels, or model constants from the MATLAB harness.
Those are properties of the official C implementation and its compiled
weights. Calling the executable is not equivalent to reimplementing them.

## 12. Limitations and reproducibility cautions

1. **Wrapper versus implementation:** MATLAB orchestrates the official
   executable; it does not contain the RNNoise neural network.
2. **Desktop dependency:** Windows runs through WSL and requires a compatible
   executable, shared libraries, and permissions. Linux runs the executable
   directly.
3. **PCM quantization:** the reference path is signed PCM16, with scaling and
   quantization before RNNoise. A direct float API port will not be
   bit-identical unless it deliberately reproduces this transport.
4. **Demo warm-up:** the first 480-sample output frame is discarded by the
   local `rnnoise_demo.c`.
5. **Finite boundaries:** FIR zero extension and frame zero padding create
   transients; alignment and metrics must be reported with their bounds.
6. **Metrics:** SNR improvement depends on the selected clean reference,
   noise, prefix, scaling, delay, and padding. It is not a universal quality
   score.
7. **Toolbox independence:** production FIR conversion does not require
   Signal Processing Toolbox; comparison does.
8. **Generated artifacts:** binary outputs depend on the executable build,
   model, platform, and input files. Metadata should accompany every claim.
9. **GUI parity:** the GUI is intentionally thin but saves less metadata than
   the non-GUI entry point.
10. **No real-time claim:** MATLAB loops, WSL process startup, file I/O, and
    plotting are not a real-time implementation.

## 13. Later CCS/C6713 portability plan

Porting should proceed in separately validated stages:

1. **Input/resampler:** export `fir_coefficients.mat` as `const float
   fir[6][97]`; implement a fixed circular history and six phase MACs.
2. **Frame transport:** use static 480-sample buffers and reproduce the
   documented PCM16 conversion if matching this reference; otherwise compare
   against a direct-float reference separately.
3. **RNNoise state:** port the official source/API and model with one persistent
   state across frames. Do not reset state at a frame boundary.
4. **Numerics:** choose and document float/fixed-point behavior, saturation,
   alignment, and compiler/SIMD differences. Avoid desktop file I/O, dynamic
   allocation, WSL, MATLAB GUI, and x86-specific paths.
5. **Validation:** compare frame-by-frame host-C and CCS output against the
   exported vectors, then measure maximum/RMS error, state memory, linker map,
   and cycles per 480-sample frame.
6. **System integration:** if the DSP receives 8 kHz audio, include FIR cost
   and buffering in the real-time budget; if it receives 48 kHz audio, the
   FIR may remain an offline/front-end step.

The exported vectors are golden preparation/reference data, not proof that a
future port is correct. A successful port must document the exact official
source revision, model weights, compiler options, numeric format, and
sample-by-sample comparison procedure.
